# BF Workbook — Schema 驱动的业务文档运行时

> **一句话**：用一份 `BFDocumentSchema v4.1.1` 描述业务数据，同一份 schema 同时驱动
> **表单录入 → 分页文档 → Sheet 台账 → PDF 二进制输出**。

本 Storybook 是给 **开发者** 与 **使用者** 建立生产落地信心的入口。使用 `StoryShell` 包装的
story 会附带**可复制的示例代码**与**实时数据树**；没有包装的 story（如 Quick Start 的 API 示例）
只展示运行时行为。无障碍由 e2e 里的 axe 扫描守着（3 个核心 story + 全部 docs 页）。

---

## 为什么用它？

| 关注点 | BF Workbook 的答案 |
|--------|-------------------|
| 上手成本 | `SimpleForm` 5 行字段定义即可渲染完整表单，零 Schema 知识 |
| 复用与一致 | Schema 驱动，表单 / 页面 / 表格 / PDF 由同一份数据与规则驱动 |
| 复杂业务 | 校验、依赖引擎、条件引擎、插件体系、i18n、Hook 生命周期 |
| 交付安全 | 内置 XSS 清洗、三级错误边界、PDF-1.7 纯字节输出（无外部依赖） |

## 快速开始（5 分钟）

```tsx
import { SimpleForm } from "@byteforce/workbook/quick";

export function OrderForm() {
  return (
    <SimpleForm
      fields={[
        { name: "customerName", type: "text", label: "客户名称", required: true },
        { name: "amount", type: "number", label: "订单金额" },
        { name: "deliveryDate", type: "date", label: "交付日期" },
      ]}
      onSubmit={(data) => console.log("提交", data)}
    />
  );
}
```

> 👉 在左侧导航 **Quick Start / SimpleForm** 中直接体验，右侧「查看示例代码」可复制。

## 生产就绪度

- ✅ **能力覆盖**：{storyCount} 个 story 覆盖 16 个能力域（form / page / sheet / editor / runtime / plugins）
- ✅ **一致性容器**：`StoryShell` 统一提供标题、能力标签与示例代码面板
- ✅ **无障碍**：3 个核心 story 与 {docPageCount} 个 docs 页在 e2e 中跑 axe（WCAG 2.0/2.1 A+AA），违规即失败
- ✅ **e2e 守护**：{testCount} 条 Playwright 用例（{specCount} 个 spec）覆盖能力级 story，防止回归
- ✅ **静态构建**：`pnpm build-storybook` 产出可部署的 `storybook-static/`

> 上述数字来自 `stories/storybookStats.ts`，并由 `stories/storybookStats.test.ts` 对照
> `stories/*.stories.tsx` 与 `tests/e2e/*.spec.ts` 校验——改故事或改测试会让单测变红。

## 给使用者的建议路径

1. **评估能力**：先看「生产样张」—— 同一 schema 驱动 form → page → sheet → PDF
2. **验证场景**：在对应能力域 story 中修改字段，观察数据树与错误状态是否符合业务预期
3. **复制落地**：`StoryShell` 包装的 story 可在「查看示例代码」中展开完整片段并复制
4. **查 API**：每个能力域的 docs 页有「适用场景 / 最小示例 / API / 边界 / 源码」五段说明

> 所有能力均可在本 Storybook 中交互验证；问题与建议欢迎通过 GitHub Issues 反馈。
